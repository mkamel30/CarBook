## ما هو CarBook

CarBook دفتر شخصي للسيارة: يسجّل ما تضعه في الخزان، وما فعلته الورشة بالسيارة، وما هو مستحق قادم — ثم يقول لك الحقيقة في الأرقام بدل تقريبها وإخفائها.

مكتوب لمالك واحد ببيانات حقيقية، لا للوحات تحكم أساطيل المركبات. كل شيء يعمل على ملف SQLite واحد، بلا أي خدمة خلفية من طرف ثالث، وبلا أي تحليلات تتبّع.

ما تستطيع فعله به:

- **تسجيل الوقود بأرقام دقيقة.** اللترات والتكلفة الإجمالية يحسب كلٌّ منهما الآخر من سعر اللتر، والكسور العشرية تُحفظ كما أُدخلت (`40.584 لتر` تبقى `40.584 لتر`).
- **قراءة استهلاك حقيقي.** المسافة و`لتر/100 كم` و`كم/لتر` وتكلفة الكيلومتر تُحسب بين التفويلات **الكاملة** فقط. التفويلة الجزئية تُحفظ في السجل، لكنها لا تظهر كرقم استهلاك، لأن القسمة على مسافة مجهولة تُنتج رقماً يبدو دقيقاً وهو ليس كذلك.
- **تفصيل فواتير الصيانة.** أكثر من قطعة غيار في الخدمة الواحدة، كل قطعة مُعلَّمة عليها «جديد أصلي» أو «استيراد/مستعمل»، مع جمع تلقائي لقطع الغيار والمصنعية.
- **تنبيهات الصيانة الدورية.** الزيت والفلاتر والبوجيهات والفرامل وسائل التبريد وزيت الفتيس تُقيَّم على الكيلومترات وعلى الزمن المنقضي معاً، وتظهر كـ*سليمة* أو *مستحقة قريباً* أو *متأخرة*. ويمكنك ضبط نقطة الأساس بنفسك — إذا تغيّرت البوجيهات فعلاً عند 50,000 كم فقل ذلك، ويبدأ العدّ التنازلي من هناك.
- **مواصفات المصنع في متناول يدك.** لزوجة الزيت وسعته، نوع زيت الفتيس (ATF/CVT)، مواصفة سائل التبريد وسائل الفرامل، ضغط الإطارات البارد، سعة الخزان، الأوكتان الموصى به، نوع البوجيهات ومواصفة البطارية — تُبحث مرة واحدة وتُحفظ في قاعدة البيانات.
- **اسأل طبيب السيارة الذكي.** يجيب وبيانات سيارتك داخل السياق: الماركة والموديل والسنة وقراءة العداد الحالية وآخر خمس خدمات، فتكون النصيحة عن سيارتك لا عن السيارات عموماً.
- **تصدير وطباعة.** ملفات Excel متعددة الأوراق (الصيانة والوقود والمواصفات)، وتقرير فحص منسّق على مقاس A4 للمشتري أو للمفتش.
- **نسخ احتياطي لسجلاتك.** تصدير JSON لكل سيارة وتفويلة وفاتورة وجدول دوري، واستعادة افتراضية بنمط *الدمج* — تُعيد إضافة السجلات الناقصة ولا تستبدل الموجود أبداً. أما التفضيلات (أسعار الوقود والثيم واللغة) فليست جزءاً من هذا الملف.

ثلاث لغات مدمجة: **العربية** (RTL بخط Cairo) و**الإنجليزية** و**البولندية**. وأربعة ثيمات: Material 3 Expressive (الافتراضي) وGlassmorphism وLight Minimal وTerminal.

## كيف بُني التطبيق

| الطبقة | التقنية |
| :--- | :--- |
| تطبيق الويب والـ API | Next.js 15.5 (App Router) وReact 19.3 وTypeScript 5.7 |
| التنسيق والواجهات | Tailwind CSS 3.4، ثيمات بمتغيرات CSS، أيقونات Lucide، خط Cairo من Google |
| قاعدة البيانات | SQLite عبر `@libsql/client`، وDrizzle ORM للقراءة، وSQL مُعاملِي (parameterised) لمحرك المزامنة |
| التحقق من البيانات | Zod 3.24 (مخططات النطاق على كل عملية كتابة) |
| جداول البيانات | `xlsx` (SheetJS) |
| غلاف الأجهزة المحمولة | Capacitor 8.6 + تطبيق Vite/React منفصل في [`mobile/`](mobile/) مع WatermelonDB 0.28 |
| الاختبارات | Vitest 3 — 114 اختباراً في 18 ملفاً |

يحتوي المستودع على تطبيقين:

```
src/            تطبيق Next.js: الواجهات ومسارات API والخدمات والتخزين
  app/api/        16 معالج مسار (vehicles, fuel, maintenance, schedules,
                  reports, settings, backup, sync, auth/*, ai/*)
  domain/         مخططات Zod — التعريف الوحيد للبيانات الصحيحة
  persistence/    db.ts (الاتصال والترحيلات)، repository.ts، sync.ts
  services/       calculator, ai, aiOrchestrator, automotiveDatabase,
                  exportExcel, backup, auth, authz, deviceAuth
  i18n/           محلل ملفات .cfg + قواميس ar/en/pl
  theme/          سياق الثيمات وتعريفات الرموز
mobile/         عميل دون اتصال بـ Vite + React + WatermelonDB (هدف Capacitor)
docs/           ARCHITECTURE.md وAPI.md وDEPLOYMENT.md
tests/          مجموعة اختبارات الخادم
```

التفصيل الكامل في [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## الحسابات والملكية والعمل دون اتصال

بدأ CarBook كأداة محلية لمستخدم واحد، ثم أُضيف إليه نظام حسابات، لذا من المفيد تحديد الوضع بدقة.

**كل سجل له مالك.** `vehicles.user_id` يملك السيارة، وسجلات الوقود والصيانة والجداول الدورية ترث الملكية من سيارتها. كل معالج API يتحقق من هوية المستدعي أولاً ثم من ملكية السجل ثانياً. والسجل الذي لا تملكه والسجل غير الموجود يجيبان كلاهما بـ`404`، فلا يمكن فحص المعرفات لمعرفة أيهما أيهما. والمستدعي المجهول يحصل على قائمة فارغة، لا على السجلات القديمة غير المسندة.

**وضع الضيف حساب حقيقي وليس قيمة فارغة.** الجهاز الذي لم يسجّل الدخول يُسجَّل كـ`guest:<deviceId>` مع `is_guest = 1`. بيانات الضيف معزولة وقابلة للقراءة والمزامنة بلا حالات خاصة، وربطها بحساب حقيقي يعيد إسناد السيارات وسجلاتها في معاملة واحدة (transaction) ويعيد ختم تسلسل المزامنة حتى تسحب أجهزة الحساب الأخرى التاريخ المدمج.

**المزامنة مؤشّر وليست فروقاً.** كل سجل يحمل `rev` (إصدار السجل) و`seq` (عدّاد عام تصاعدي) و`deleted` (شاهد حذف)، و`sync_ts` يقرّر الأسبقية لآخر كتابة. يطلب الجهاز كل ما `seq > since`، ويرفع سجلاته المتسخة، ويطبّق الرد، ثم يتقدّم بالمؤشر — ولا يمسح علامة «متسخ» إلا للإصدار الذي قبله الخادم بالضبط، فلا يضيع تعديل أُجري أثناء تنفيذ الطلب.

**الوضع الصادق لعمل «دون اتصال».** عقد المزامنة وطبقة بيانات الجهاز ومسار الضيف/الربط منفَّذة ومختبرة من طرف إلى طرف داخل العملية. وما هو **غير** مكتمل:

- غلاف Capacitor ما زال يشير إلى الموقع البعيد (`server.url`) بدل `webDir` مضمّن، فلا يعمل أي كود على الجهاز بعد، والعمل دون اتصال الحقيقي غير متاح على الهاتف.
- لا توجد آلية تسليم من OAuth إلى الجهاز. `PUT /api/auth/device` يحتاج رمز حساب حقيقياً، ولا يوجد تحويل برمز لمرة واحدة يعود إلى التطبيق بعد تسجيل الدخول في المتصفح.
- HTTPS على الخادم شرط أساسي للاثنين أعلاه، وهو غير مُعدّ بعد.

راجع قسم خارطة الطريق في [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## التثبيت والتشغيل المحلي

المتطلبات: Node.js إصدار 18.18 فأعلى (التطوير تم على v24).

```bash
git clone https://github.com/mkamel30/CarBook.git
cd CarBook
npm install          # أو: pnpm install
cp .env.example .env.local
npm run dev          # http://localhost:3070
```

تُنشأ قاعدة البيانات عند أول تشغيل في `car_maintenance.db` بجذر المشروع. وغيّر مكانها بـ`CARBOOK_DB_PATH` — بهذه الطريقة يُبقي النشرُ البيانات خارج مجلد المستودع، وتجتنب مجموعة الاختبارات لمسها.

تسجيل الدخول بجوجل يحتاج قيمتي `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` حقيقيتين وعنوان إعادة توجيه مسجّلاً؛ ومع بقاء القيم الوهمية يردّ جوجل بـ`401 invalid_client`. وكل شيء آخر في التطبيق يعمل دون تسجيل دخول.

```bash
npm test             # 114 اختباراً، وتشمل مجموعة mobile
npm run typecheck    # tsc --noEmit بوضع strict
npm run build        # بناء نسخة الإنتاج
```

عميل الأجهزة المحمولة مشروع منفصل:

```bash
cd mobile
npm install
npm test             # 18 اختباراً: سلوك مخزن الجهاز + مزامنة e2e بين الجهاز والخادم
npm run build
```

## الخصوصية والأمان

ما هو مُطبَّق فعلاً، وما ليس كذلك:

- **تفويض على كل مسار.** `requireUser` للجلسة و`requireOwnership` للسجل، وكلاهما في [`src/services/authz.ts`](src/services/authz.ts). أسماء الجداول التي تصل إلى SQL تأتي من قائمة مسموحات، لا من الطلب أبداً. والقيم دائماً مُعاملِية.
- **إدارة الجلسات.** كوكي `carbook_session` بعمر 30 يوماً و`httpOnly` للمتصفح، ورمز حامل بعمر 15 دقيقة لغلاف الجهاز. ويجب أن يبقى `JWT_SECRET` ثابتاً بين إعادة التشغيل وإلا سقطت كل الجلسات. وفي الإنتاج يكون الكوكي `secure`، ولهذا فإن HTTPS ليس اختيارياً.
- **رموز الأجهزة.** يُخزَّن بصمة SHA-256 لرمز التحديث فقط. والرموز تتبدّل عند الاستخدام؛ وإعادة استخدام رمز قديم تُعامل كسرقة وتُلغي جلسات الجهاز. والرمز مرتبط بالجهاز الذي أصدره.
- **طلبات الذكاء الاصطناعي.** الاتصالات الصادرة تشترط HTTPS صريحاً، وترفض بيانات الاعتماد المضمّنة في الرابط، وترفض عناوين loopback وRFC 1918 وCGNAT وlink-local وعناوين IPv6 المحلية ومتعددة البث وعناوين البيانات الوصفية السحابية بكل تهجئات `inet_aton` (النقاطي العشري، العشري، الثماني، الست عشري، المختصر). ولا يُتبع أي تحويل (redirect)، لأن اتباعه سيعيد إرسال مفتاح الحامل إلى هدف التحويل. وكل طلب يحمل مهلة زمنية. وإعادة المحاولة محدودة بثلاث، والفشل الدائم (بيانات اعتماد خاطئة، رابط مرفوض) يخرج من الحلقة من المحاولة الأولى بدل استهلاك الحصة ثلاث مرات.
  - *حد معروف:* هذا يتحقق من نص الرابط. أما اسم النطاق الذي يُترجَم إلى عنوان خاص — DNS rebinding — فيحتاج «ترجمة ثم اتصال» في طبقة تستطيع الاحتفاظ بمقبس شبكة، وهذه الطبقة ليست كذلك.
- **الأسرار.** مفاتيح الذكاء الاصطناعي في جدول `app_settings` أو في البيئة، ولا تُضمَّن أبداً في جافاسكريبت الواجهة، و`/api/settings` لا يعيد إلا صورة مقنّعة منها.
- **بلا تتبّع.** لا تحليلات، ولا تتبّع، ولا أي نداء لطرف ثالث إلا مزوّد الذكاء الاصطناعي الذي تُعدّه بنفسك.

## إضافة لغة جديدة

القواميس وقت التشغيل وحدات TypeScript في [`src/i18n/`](src/i18n/) (`ar_cfg.ts` و`en_cfg.ts` و`pl_cfg.ts`)، تُحلَّل من نص `.cfg` بصيغة مفتاح=قيمة عند التحميل. ويحتوي `src/locales/` على الأصول القابلة للتحرير للعربية والإنجليزية؛ أما البولندية فتوجد حالياً كقاموس TS فقط.

لإضافة لغة: انسخ قاموساً موجوداً، وسجّله في `SUPPORTED_LANGUAGES` داخل [`src/i18n/config.ts`](src/i18n/config.ts)، وترجم. والمفاتيح الناقصة ترجع إلى الإنجليزية ثم العربية ثم نص المفتاح نفسه، فترجمة نصف مكتملة تُعرض ولا تنكسر.

نصوص المحتوى يجب أن تتفرّع على `lang !== 'ar'` (عربية مقابل البديل الإنجليزي)، لا على `lang === 'en'` — الثانية تُظهر الإنجليزية بصمت لكل لغة أخرى.
